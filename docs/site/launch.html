No proof, no claim

Three verdicts. Every claim gets one.

Every notes tool can write you a summary. The problem with all of them is that you cannot tell which sentences are real. So a blocking gate checks every citation before anything reaches you.

Verified
citation resolves → segment supports the claim

The claim ships with a chip you can click. It scrolls the transcript to the exact line and plays the moment. This is the only state that reads as clean.

Flagged
citation resolves → segment does not visibly support it

The claim ships flagged, not quietly mixed in with the verified ones. The call gets a Partial status in the list, so a half-trustworthy set of notes never masquerades as a whole one.

Dropped
citation points at a segment that does not exist

The claim is deleted, and the deletion is logged with a reason. The counter in the top bar — 18 claims blocked — is that log, in public, on every screen.

The app shows you what it threw away. Notes you cannot audit are just a confident guess. Ask any other tool in this category to show you its rejected claims.

How it works

Six steps, one of which is allowed to say no.

The model drafts. It does not decide what ships.

Input
Audio
mp3 · wav · a URL
Transcribe
PyAI Hear
channel for stereo, diarize for mono
Index
Segments
seg_000… assigned once, here
Extract
Claude
schema-forced output
Untrusted
Draft
claims + cited segment ids
Blocking
Citation gate
drops · flags · logs
Output
Notes + receipts
shipped · partial · failed

Segment ids are assigned once, at transcription, and are never regenerated or invented by a model — which is what makes a citation checkable at all. Extraction uses output_config.format to force a schema, so there is no free-text JSON parsing and no parse-and-repair loop anywhere in the codebase. Swapping any provider is one line in lib/registry/index.ts.

What you get

The whole job after a call.

What happened, what did they push back on, what do I do next — and the receipt for each answer.

Exact speaker separation

Stereo with one party per channel is split by channel — no model guessing who spoke. Mono falls back to the diarizer, and the call header always says which one it used.

Judgement lives in markdown

What counts as a real objection, when a commitment is verifiable — that lives in skills/<id>/SKILL.md, editable by a salesperson, not buried in a string literal.

Commitments that survive the call

A verified next step stays open until something settles it. The next call must cite a line to close it — silence closes nothing, and a percentage always ships with its denominator.

Deal score, five methodologies

MEDPICC, BANT, SPICED, CHAMP or ANUM. A criterion with no resolvable citation scores zero and says so, rather than being padded into a friendlier number.

CRM payload you can read first

See the exact document a HubSpot push would post — real property names, types and units — with no client and no credential in the app. Nothing is sent, because nothing can be.

Test the gate yourself

One button on every call feeds the gate a fabricated claim and shows you it being rejected. The trust story is a feature you can press, not a paragraph you have to believe.

Five-minute setup

No key. No signup. No database.

One command sorts out Node, clones the repo, installs, asks for your keys — and proves the pipeline on a real call before it tells you it worked.

zsh — king-gong
$ curl -fsSL https://raw.githubusercontent.com/AshmitGupta-slbs/king-gong-hackathon/main/install.sh | bash
Sturdier if your shell has it: bash <(curl -fsSL …/install.sh) — that hands bash a file descriptor instead of a pipe, so your keyboard stays on stdin and the setup prompts cannot answer themselves.
Then pick a surface
$ cd king-gong && npm run dev # the web app, http://localhost:3000
$ cd king-gong && ./kg # the terminal UI
Already cloned it?
$ npm ci && ./setup.sh # keys, checks, and a real end-to-end run
→ Five fully-analysed sample calls are already there, and they need no key at all. · Full walkthrough in ONBOARDING.md; ./kg doctor says what is configured and what is wrong.
Node 22.13+
For the built-in node:sqlite — which is why there is no database to install. Not 22.5: it landed there but stayed behind --experimental-sqlite until 22.13, so 22.5–22.12 pass a version check and then throw on the first query. node scripts/node-check.cjs tests the capability, not the number — and the installer fetches a good Node if you need one.
One key, ideally
A pyai_live_ key carrying recap:read runs the whole app — PyAI transcribes the call and writes the notes. Setup reads the scopes off your key and tells you which case you are in. Recap takes no prompt and returns no citations, so claims are matched back to lines here and unsupported ones ship flagged, not deleted.
Or bring your own model
ANTHROPIC_API_KEY, or AWS Bedrock credentials — setup picks up whichever you already have exported. With neither, notes fall back to a keyword stub that is loudly labelled in the UI.
Or press Enter twice
The five bundled calls are fully analysed and need no credential. A sandbox PyAI key mints itself for live calls, but the allowance is budgeted per network — on shared wifi it can already be spent, and a real key sidesteps it.
