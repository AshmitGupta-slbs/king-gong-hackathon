§ 08 · Built vs pending vs usable

What actually works.

No status word is used loosely on this page. "Working" means there is a test or a browser check behind it. "Unverified" means the code exists and has never run against the real thing. "Blocked" means something outside the code is missing.

In one line: the pipeline, the gate, the harness and the UI are built and verified. Extraction has since run for real on Bedrock in the deployed environment. What has not changed is the five committed samples: their notes were hand-authored for the demo, and the app says so wherever they appear.

252 automated checks pass across four suites, plus a 27-item ship checklist with exactly one red line — and it is deliberately red. See § 11 · Scorecard for what that red costs.

Usable right now, with no setup at all

Clone, npm install, npm run dev. Measured at 11 seconds from copy to serving, with no key, no signup and no network calls needed for any of the following:

WORKS TODAY
Five analysed calls

Real PyAI transcripts, real speaker separation, real timestamps. Clean close, heavy objections, competitor named, pricing pushback, and one that goes nowhere.

WORKS TODAY
Click a claim → hear it

Citation chips seek the audio to the exact second and highlight the line. Verified in a real browser: clicking seg_003 · 0:18 put audio.currentTime at 20.2s against a segment starting at 18.0s.

WORKS TODAY
Test the gate, live

A button on every call page feeds fabricated claims through the real gate: 3 dropped, 2 flagged, status → partial, counter increments.

WORKS TODAY
See where display ≠ ASR

The one transform that changes words — a spoken digit run collapsed to 1400 — is underlined, and hovering names what was actually said. The Markdown export footnotes every substitution.

WORKS TODAY
Export and share

Markdown (readable, with quotes and timestamps inline, plus a rejections table), JSON (verbatim), and a read-only share link per call.

And with a PyAI sandbox key — which mints itself automatically on first use, no signup — you can also upload your own call and watch it transcribe, and watch the usage counter move. One caveat on that key: the free mint allowance is budgeted per network, not per account, and it can run out — see §10, open risks. It has already run out once from this machine. Nothing above this paragraph depends on it.

What is blocked, and by exactly what

THE ONE BLOCKER THAT MATTERS
The committed samples were written by hand, not by a model

Extraction itself is no longer unproven — it runs on Bedrock in the deployed environment. But the five sample results in this repo were hand-authored for the demo, so a clone with no credential shows notes no model wrote. Their citations are real and were resolved by the real gate; the prose was not generated.

What unblocks it: either ANTHROPIC_API_KEY, or AWS credentials plus Anthropic model access in the Bedrock console. Then one command — npm run extract:samples — regenerates all five sets of notes without re-recording audio or re-burning PyAI minutes.

Until then extracted_by reads demo-fixture, and the app says so wherever those notes appear rather than letting them pass as model output. check:ship refuses to pass — that is the one deliberate red, and it is the single highest-leverage thing left to fix.

Working but unverified — and why that distinction matters

Two things run and appear correct but have no proof behind them, and it would be easy to let them pass as "working":

ThingWhat is missing
The five-minute setup, on a machine nobody has touchedThree commands, no native compilation and no credential needed — but the checklist asks for it timed, on a clean machine, by someone who has not seen the code, and that run has not happened. The one risk it would expose: Node must be ≥22.5.
The demo, rehearsedEvery beat works individually. Nobody has run the whole script twice, timed, on the real setup path — which is what the brief actually asks for.
Model-judged action-item outcomesThe gate path, the storage and the UI are covered by 14 and 14 checks respectively, and the prompt carries the open items. The end-to-end judgement — a real model reading call B and closing a commitment from call A — needs a credential and has not been watched.

Deliberately not built

These are absent by choice. Adding any of them would have come out of the citation loop, which is the product.

CRM sync deal scoring forecasting multi-tenant auth billing live on-stage transcription PyAI Trace coaching dashboards the stream-per-channel ingest fallback

The last one is worth a note: it was fully designed as a contingency in case transcribe:jobs turned out to be denied. It was not, so the design was dropped and recorded in docs/api-truth.md so nobody rebuilds it.

One of those chips needs a footnote, and one has left the list entirely, because the truth got more specific.

CRM sync remains absent and there is now a check that keeps it absent: check:ship fails the build if a HubSpot client or credential appears anywhere in app/, lib/, components/ or scripts/. What the app does have is a read-only CRM payload preview — the exact JSON a push would post, with every claim linking back to the moment that proves it, and no way to send it. The brief lists CRM sync as out of scope, so that adjacency is flagged in the scorecard rather than left in a commit message.

PyAI Recap has moved off this list. It was blocked by a credential rather than a preference — the self-minting sandbox key carries neither recap:read nor recap:configure — and a live key that carries both turns it on. It is now a selectable notes engine: LLM_PROVIDER=recap, or the Notes engine picker on the home page, which overrides the default for one upload so the two engines can be compared on the same call.

Claude is still the default, deliberately, and here is the honest reason. Recap accepts no system prompt, so the skills/ corpus and account context cannot reach it and it judges no commitments carried in from earlier calls — the harness therefore records skills_used as empty rather than as the corpus that was merely loaded. And Recap returns no citations, so each claim is matched back to a transcript line by this repo rather than asserted by the engine. Because a matched citation always resolves, the gate's delete path is unreachable for Recap output: an unsupported claim ships visibly flagged on a partial run instead of being removed. That is a genuinely weaker form of the guarantee this product is built on, so it is stated on every call Recap produces rather than left in a doc.
