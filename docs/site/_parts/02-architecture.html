§ 02 · Architecture

How it is put together.

One Next.js application, one SQLite file, no other services. Audio goes in at one end; verified, cited notes come out at the other. Everything between is four steps and a gate.

In one line: audio → PyAI Hear (transcript with speakers) → Claude (draft notes citing segment ids) → the citation gate (deletes or flags anything unprovable) → notes with receipts.

The only external service on the request path is PyAI. There is no database server, no queue, no worker, and — deliberately — no native dependency anywhere. A clone runs with npm install && npm run dev and nothing else.

Two things about this diagram are load-bearing.

First, the model never talks to the user. Its output is a draft that goes to the gate, and only the gate's output reaches a screen. That is why §03 makes such a point of ExtractionDraft and ExtractionResult being different types.

Second, rejections are a product surface, not a log line. They go into the database, into the UI, and into the Markdown export.

The request path

One function orchestrates everything: processCall() in lib/harness/loop.ts. It is the only place the seven harness parts meet, and it always ends in exactly one of four statuses.

  1. Open a run record — before any work

    openRun() writes a row immediately. If the process is killed two lines later, that row still exists and gets reconciled to failed on next boot. This ordering is the whole failure invariant.

  2. Transcribe via the registry

    getSTT() returns whichever provider is configured — real PyAI, or the fixture provider that replays committed sample transcripts with no network. Wrapped in a bounded retry that treats 4xx as fatal and 429/5xx as retryable.

  3. Persist the call and its segments

    Segment ids are assigned here, once, and never regenerated. Usage is recorded from result.audio_seconds.

  4. Extract, then gate — with the gate's complaint feeding the retry

    The budget governor runs preflight() before the model call. The model returns a draft; the gate verifies it. If the gate had to delete claims for citing segments that do not exist, that exact complaint is passed into the next attempt's prompt. This is what makes the retry aimed rather than hopeful.

  5. Close the run with one terminal status

    shipped, partial, failed, or deadline — written in a finally block, so it happens whether the body succeeded or threw.

43 source files, about 5,900 lines. The interesting quarter of it:

One rule is enforced automatically: npm run check:ship fails if any file outside lib/registry/providers/ imports @anthropic-ai/*. The registry stops being useful the moment something bypasses it, so that is a test rather than a convention.

Stack choices that mattered

STORAGE
node:sqlite, not better-sqlite3

Node ships SQLite built in. That means no node-gyp, no compiler, no prebuilt-binary roulette on a stranger's laptop — a failed native build is the classic way a five-minute setup becomes forty.

cost: null-prototype rows, see below
FRAMEWORK
Next.js 16, one process

API routes and UI in one app, so npm run dev is the entire runtime. Server components read SQLite directly; the workspace is the one client component.

React 19 · Tailwind 4 · Turbopack

Choosing the built-in SQLite had a real cost, found by running it rather than by reading about it: node:sqlite returns rows with a null prototype, and React Server Components refuse to serialize those to client components. Every call page returned a 500 until lib/db.ts was changed to rebuild plain objects explicitly instead of casting the driver row.

That turned out to be better practice anyway — a schema change now surfaces as a TypeScript error in one file, rather than as undefined in the UI.

Storage

Six tables, one file at data/opengong.db (gitignored). The two that are less obvious:

TableWhy it exists
runsThe failure invariant. A row is written before work starts and updated on exit, so a crashed process leaves a reconcilable record rather than a mystery.
gate_rejectionsEvery claim the gate dropped or flagged, with a reason. Read by the UI and the export — a silently discarded claim is indistinguishable from one never made.
usage_eventsAudio seconds and model tokens, from real work only. Replaying a committed sample records nothing.
