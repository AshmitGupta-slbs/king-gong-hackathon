§ 10 · Decisions & open risks

What we chose, and what we do not know.

Several decisions here had more than one defensible answer. Picking one silently is the failure mode worth avoiding, so each is written with the alternative it rejected. The page opens with the unresolved problem rather than burying it.

The one to read — now measured, and the answer is good. PyAI Hear invents fluent, confident sentences out of silence on its streaming path, and our citation gate could not detect that: it checks that a quote matches the transcript, not that the transcript matches the audio. This page carried it as the project's highest-consequence unknown for as long as it was one. It has now been tested on the path we actually ingest with, and the batch path is clean.

Everything else on this page is a settled decision with reasoning attached.

The risk that mattered most — and how it resolved

STREAMING PATH · REAL DEFECT
Hear fabricates speech from silence

On the streaming path, with nobody speaking, Hear repeatedly emitted confident finals — confidence 0.99+, endpoint_reason: silence — containing sentences that were never said. Measured input level: real speech RMS 0.219; the ambience windows that produced fabricated text, RMS 0.035.

Why this is a product problem and not an API curiosity:

  1. The gate's guarantee is narrower than it sounds

    It verifies that a claim's citation resolves to a real segment, and that the segment's text supports the claim. It has no way to know whether the segment's text is faithful to the audio.

  2. So a fabricated segment becomes quotable evidence

    If a transcript segment contains invented speech, a claim citing it passes the gate cleanly — the quote really is right there in the transcript. It would be rendered with a citation chip, a timestamp, and an amber-free verified badge.

  3. Real calls are full of silence

    Hold music, mute, a pause while someone reads a document. Exactly the conditions that produced fabrication in the probe.

BATCH PATH · MEASURED CLEAN
The path we actually ingest with does not do this

scripts/probe/batch_silence_probe.py submits speech · gap · speech and checks whether any returned segment lands in the gap. Both kinds of gap were run, including the one that mattered:

25s of digital silence (exact zeroes) → 2 segments, both real speech, nothing in the gap. 20s of room tone at RMS 0.035, the exact level that fabricated finals on the stream → 2 segments, both real speech, nothing in the gap.

The second is the one that counts: a path that fabricates on ambience tells you nothing about its behaviour on exact zeroes, so testing only digital silence would have proved the easy case and left the real one open.

The question was never "does Hear fabricate" but "does the path we ship fabricate". Naming that distinction is what made it testable — and the answer is no.

So the defect is specific to streaming. Dead air on an uploaded recording cannot manufacture a quotable segment, and no input-level gate was built at ingest — which is now a measured decision rather than an omission. Anything that later moves ingest onto hear:stream reopens this and would need one; the probe already implements it as --silence-floor, default RMS 0.08.

Worth stating as a positive rather than an absent bug: the citation gate's guarantee holds end-to-end on the path this product uses, because the transcript it verifies against is faithful to the audio. That was an assumption until it was measured, and it got measured because it was written down as an assumption instead of being quietly assumed.

The decisions

i

Nine calls, each with its rejected alternative

·
1 · Content-word overlap for tier 2, not an LLM judge

Rejected: an LLM-as-judge second pass, which would be more semantically accurate.

Why: it adds a model call to every extraction and cannot be shown to be deterministic on stage. Overlap is free, instant, reproducible and explainable — here is the score, here is the threshold. It is the obvious upgrade path if precision becomes the bottleneck.

2 · Tier 2 gates assertions, not abstractions

Applying claim-support scoring to an intent label was a category error, caught by the first test run: price-sensitive scored 0.00 against its own correct evidence.

So tier 2 covers objections and next steps; intent labels, key-moment notes and the email draft get tier 1 only. Their support score is still stored, so the exemption is auditable rather than invisible.

3 · List claims are dropped, singleton deliverables are flagged

Rejected: one uniform rule.

Why: a dropped objection leaves a coherent output. A dropped follow-up email leaves a hole a reader misreads as "nothing to follow up". Singletons therefore ship marked unverified with unresolvable ids stripped, and force run_status to partial.

4 · Draft and result are different types

A deliberate divergence from the reference spec, which put run_status on the extraction shape. Splitting them makes it structurally impossible for a model to declare its own output shipped.

5 · node:sqlite instead of better-sqlite3

Why: zero native dependencies. No node-gyp, no compiler, no prebuilt-binary roulette — a failed native build is the classic way a five-minute setup becomes forty.

Cost, found by running it: null-prototype rows that React Server Components refuse to serialize. Every call page 500'd until the DB layer rebuilt plain objects explicitly. That turned out to be better practice anyway.

6 · Sample audio is synthesised, rep on the left channel

Five written calls, synthesised per speaker and interleaved to stereo. No customer audio and no PII in a public repo, exact ground-truth speaker separation via channel: true, and a demo that needs no setup because the WAVs are committed.

The rep-on-left convention is load-bearing — the provider maps channel 0 to rep. Change it in both places or neither.

7 · The keyword stub exists, and cannot become the demo

It unblocked the UI, routes, export and harness verification behind a missing credential. The hazard is obvious, so provenance is enforced by tooling: extracted_by persisted per result, one shared definition of "real output", a permanent UI banner, and a failing ship check.

8 · A partial regeneration is worse than none

A failed sample rebuild left three calls on 24 kHz PyAI audio paired with transcripts from the 16 kHz say audio. Everything looked correct while every citation pointed at the wrong moment — a total product failure presented as a working demo.

Now asserted as an audio/transcript drift check in check:ship, with reindex:samples to recover a half-finished run.

9 · Quota 429s are terminal, not retryable

Measured: daily_cap_exceeded survives minutes of backoff. Treating it as retryable meant burning a run's whole wall clock before failing anyway, so it is now terminal with an actionable message. Genuine rate limits are still retried, with a hook to honour Retry-After where a server sends one.

Why segment_ids is not enum-constrained

Structured outputs would let us constrain segment_ids to an enum of the call's real ids, making a fabricated citation structurally impossible. We do not, and the reason is not laziness.

A gate that cannot fire is decoration. "Claims blocked: 6" is the most legible honest signal this product has, and the only visible proof that verification is real rather than asserted. We would be trading a demonstrable property for an invisible one.

It is written down as the hardening move if hallucinated ids turn out to be frequent rather than occasional — one line in extract-shared.ts. Note also that it would not touch the risk at the top of this page: constraining ids prevents citing a segment that does not exist, not citing a segment that exists and is fabricated.

The readability rules — two passes, two guards

Hear returns lowercase, unpunctuated text. Making it readable means changing what is on screen, in a product whose claim is that what is on screen is faithful. So there are two separate transforms, each with its own guard, rather than one permissive one.

PASS 1 · CASING
Guarded by sameWords()

Capitalisation, acronyms, proper nouns from the call title, one terminal stop. Never inserts, removes, reorders or respells a word — asserted across all 50 committed segments.

PASS 2 · SPOKEN DIGITS
Guarded by sameSpokenNumbers()

The one place changing words is correct: figures sometimes arrive spelled out, and the request cannot control it. "one four oh oh" → "1400", verified to say the same number whichever way it is written.

Pass 2 is deliberately conservative, because it was measurably unsafe when it was not. A run must be at least four words and contain an unambiguous digit word — otherwise "oh oh oh that is a problem" became "000 that is a problem", and "we counted one two three items" became "123 items". "oh" is an interjection far more often than a digit.

Where the two error directions trade off, prefer the false negative. An unconverted "one four oh oh" is ugly and honest. A wrong "000" is neither.

What we still refuse to do is let a model insert commas and sentence breaks. That needs judgement, and judgement here means a model editing evidence. So the transcript reads better than raw ASR and still not like prose.

And the seam is shown, not hidden. Pass 2 is the only place the screen displays characters nobody said out loud, which is an odd thing to leave unmarked in a product whose claim is that what you see is faithful to the recording. So a normalised number carries a dotted underline and a tooltip naming the spoken words — spoken as "one four oh oh" — and the Markdown export, which has no hover, ends with a footnote listing every substitution by segment id. A reader can always tell which figures Hear returned and which we rendered.

The marking is presentation-only and guarded like everything else here: the marked spans are used only if re-joining them reproduces the normal rendering character for character, asserted across all 50 committed segments. If anything about the marking went wrong, the reader would get correct text with no marks rather than marked text that disagrees with the rest of the app.

Why the usage counter reads zero on a fresh clone

Replaying a committed sample records no usage, because it burns nothing — no PyAI minutes, no tokens. So a fresh clone shows 0.0 min transcribed, which looks weaker than it could.

We keep it that way. The product's entire argument is that unverifiable numbers are worthless; a usage counter that inflated itself on cached data would undercut exactly that. The demo processes a real call so the counter visibly moves.
